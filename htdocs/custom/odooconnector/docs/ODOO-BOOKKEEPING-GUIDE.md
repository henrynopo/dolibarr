# Odoo 记账与核销操作指南

（适用于 Dolibarr → Odoo 自动同步体系；受众：Odoo 端记账人员）

## 一、总体原则

1. **Dolibarr 是唯一数据源头**。所有发票、账单、定金单、退款单由系统自动推送至 Odoo，**以草稿（Draft）形式**到达，不会自动过账。
2. **记账人员的职责**：核对草稿 → 过账（Post）→ 登记收付款 → 核销。所有数值核对以 Dolibarr 单据为准。
3. **禁止**在 Odoo 手工创建与 Dolibarr 重复的发票/账单；**禁止**手工修改推送草稿的金额和行（后续同步会覆盖）。发现数据有问题：回 Dolibarr 改，等自动同步更新 Odoo 后重新过账。

## 二、单据到达 Odoo 时的固定规则

| 项目 | Odoo 中的呈现 |
|---|---|
| 编号 Number | = Dolibarr 票号（过账后保留不变） |
| Reference | = 关联的 SO / PO 号（便于对单） |
| 金额 | 发票**原始币种**（如 USD）；公司本位币折算由 Odoo 按自身汇率显示，与 Dolibarr 有小额差异属正常 |
| 记账日期 | 按系统配置取（发票日期 / 到货日 ATA 等）；**定金单和供应商退款单固定为开票日期** |
| 到达节奏 | 自动同步任务定期推送；船运 ATA 更新后，已推送草稿的记账日期会被自动修正 |

## 三、草稿结构识别（核对前先看懂行）

| 单据类型 | 草稿行结构 | Total 含义 |
|---|---|---|
| 普通发票/账单 | 1–2 行：净额（+税行） | = Dolibarr 票面总额 |
| **有定金抵扣的票** | 主行净额 + **负行**（预收/预付科目，标注 down payment 及定金单号） | = **剩余应付/应收**（票面 − 定金） |
| 定金发票本身 | 单行，挂预收（客户定金）或预付（供应商定金）科目 | = 定金金额 |
| 有 credit note 抵扣的票 | **看不到任何 CN 痕迹**——抵扣额已含在主行净额里（CN 本身不会推送） | = 抵扣后净额 |
| 费用报销 | 以供应商账单形式的草稿 | = 报销金额 |

**定金抵扣示例**（票面 17,820，已收定金 5,346）：

```
行1  销售收入            17,820
行2  预收账款(定金)       −5,346
Total                     12,474   ← 与 Dolibarr「Remaining unpaid」一致
```

## 四、日常操作流程

1. **打开待处理草稿**：按日记账筛选 Draft 状态；带 **To Review** 标记的优先处理（含义见第六节）。
2. **核对**：金额、币种、往来单位、记账日期、单据行结构与上表一致。
3. **过账**：点 Post / Confirm。编号保留 Dolibarr 票号，不会变成 Odoo 序列号。
4. **登记收付款**：Dolibarr 侧已收/付款的票，Odoo 会标记 To Review——此时在 Odoo 登记对应 payment（金额=原币金额，银行/现金日记账）。
5. **核销**：登记 payment 后 Odoo 自动按「往来单位 + 金额」匹配应收/应付；金额不一致（部分收款、多票合并付）时在核销界面手工勾选匹配。

## 五、定金业务的核销说明

定金在两个科目层面**自动清零，无需手工调账**：

```
预收/预付科目：定金发票 post 后 +5,346，正式发票的负行 −5,346  →  余额自动归 0
应收/应付层面：定金票（5,346）和正式票（12,474）各自登记 payment、各自核销
```

供应商方向（预付定金）完全对称。唯一要求：**定金发票和正式发票都要 post**，两张都过账后科目自然平。

## 六、To Review 标记的两种含义

打开单据看 **chatter（消息区）** 的说明文字：

| chatter 提示 | 含义 | 操作 |
|---|---|---|
| paid in Dolibarr … | Dolibarr 侧已收款，等你登记 payment | 登记收付款并核销 |
| Auto reset to draft: … changed after posting | Dolibarr 单据在过账后被修改，系统已把该分录**退回草稿并推入新数据** | 重新核对新值 → 再次 Post |

## 七、异常情况处理

- **Dolibarr 有单、Odoo 找不到草稿**：该票推送失败，请管理员在 Dolibarr 设置页底部 **Sync failures** 列表查看原因（修复后自动重试）。
- **同一票号出现多张草稿**（罕见）：请管理员处理，保留一张、删多余草稿，勿自行修改。
- **已过账分录 Odoo 拒绝重置**（锁期间 / 已核销行）：chatter 会提示 manual review required——需按提示手工处理。
- **记账日期随后变动**：船运到港日（ATA）更新会自动修正关联草稿的记账日期；若分录已过账则不会动，会以 To Review 提示人工确认。
